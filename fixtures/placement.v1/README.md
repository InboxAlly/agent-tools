# Synthetic placement data

All addresses use example.com. Provider labels and dates are illustrative. No email may be
sent to these addresses. The fake token is a redaction sentinel, not a credential.

`packages/cli/test/support/fixtures.mjs` loads the fixture, removes the sentinel, and gives
each test fresh relative deadlines. `test/support/server.mjs` is a loopback-only, test-only
HTTP server with synthetic allocation, quota, replay conflict, and lost-response scenarios.
`ui-events.synthetic.ndjson` contains synthetic examples of fields consumed by the public
widget. They are not recorded live responses and do not establish backend guarantees.
Result scenarios are generated by `resultSnapshot` in the fixture helper: awaiting, partial,
unclassified, complete, invalid, unknown-validity, incomplete, expired, and failed.
The HTTP fixture server can lose an allocation or read response without creating a new test.
It is excluded from the packed CLI and cannot be selected through a production CLI flag.

`results.partial.json` and `results.complete.json` are normalized synthetic response examples
using the manifest example’s original dates. They are intentionally static, not live tests.

The free-tier `quota` follows [decision 0004](../../docs/architecture/0004-service-minted-run-identity.md):
creating a test spends nothing, so the manifest shows the day's test unspent (`remaining: 1`),
and results read after the campaign arrived show it spent. Whether the deployed service returns
this block at all is part of the pending contract documentation.
